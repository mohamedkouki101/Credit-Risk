# Phased roadmap (PLAN §6 in full)

Ordered, with no calendar. ★ marks the **critical path**. Every task has: what | why | exact steps | inputs | outputs | acceptance test | dependencies. Paths are relative to the repo root (layout in PLAN §4).

```
Critical path:
E-01 → D-01 → D-02 → D-03 → D-04 → P-01 → M-01 → M-03 → M-04 → M-05 → M-06 → M-08 → M-09
```

## Phase 0: Environment and gates
**Entry:** plan approved. **Exit:** reproducible environment, licence decision recorded, CI green on an empty package.

**E-01 ★ Environment spike and version lock**
- **Why:** pins a working set of libraries. shap 0.54 and numpy 2.5 need Python ≥3.12, and OptBinning with pandas 3 is unverified.
- **Steps:** `uv init credit-risk-scorecard --package`; `uv python pin 3.12`; `uv add pandas pyarrow numpy scipy scikit-learn lightgbm optbinning shap fairlearn pandera pydantic pyyaml duckdb matplotlib fastapi uvicorn streamlit httpx`; `uv add --dev pytest pytest-cov hypothesis ruff mypy pre-commit`. Then run `scripts/smoke_env.py`, which fits OptBinning `BinningProcess` + `Scorecard` on `sklearn.datasets.make_classification` data wrapped in a pandas 3 DataFrame, fits LightGBM with `monotone_constraints`, and runs SHAP TreeExplainer on it. Time the 3 steps.
- **Inputs:** none. **Outputs:** `pyproject.toml`, `uv.lock`, `research/env_spike.md` (versions, timings, any incompatibility).
- **Acceptance:** `uv run python scripts/smoke_env.py` exits 0 on a clean clone. If OptBinning fails with pandas 3, pin `pandas<3` and record why.
- **Depends:** none.

**E-02 Repo skeleton, CI and pre-commit**
- **Why:** shows engineering discipline (signal S7) and catches regressions from day one.
- **Steps:** create the tree in PLAN §4; add `Makefile` targets (`setup data features train evaluate explain fairness report app api test lint final`); add `.github/workflows/ci.yml` (uv sync → ruff → mypy src → pytest -m "not slow"); add pre-commit hooks for ruff, an end-of-file fixer and a check that blocks files over 5 MB.
- **Outputs:** green CI badge. **Acceptance:** a PR containing one trivial test passes CI. A 6 MB dummy file is rejected by pre-commit.
- **Depends:** E-01.

**D-01 ★ Licence and access gate for the full LC file**
- **Why:** this is the primary-data decision (RESEARCH_INVENTORY C1, V2).
- **Steps:** on your machine, log in to Kaggle and open `kaggle.com/datasets/wordsforthewise/lending-club`. Screenshot the licence and file list into `research/licence_evidence/`. Create an API token, then `kaggle datasets download wordsforthewise/lending-club -p data/raw`. Record `sha256sum` of the archive.
- **Outputs:** `research/data_decision.md` stating PRIMARY = full file or Zenodo, with evidence.
- **Acceptance:** the decision file exists with a screenshot path and a hash. If the licence is not clearly permissive, PRIMARY = Zenodo.
- **Depends:** none (can run in parallel with E-01).

**P-01 ★ Pre-registration commit**
- **Why:** fixes success criteria, splits and decision rules before any model is trained (signal S2).
- **Steps:** copy PLAN §2 into `PREREGISTRATION.md`; fill in the split boundaries from `configs/splits.yaml`; commit; `git tag prereg-v1`; push the tag.
- **Acceptance:** the tag exists, and its commit date is earlier than the first commit touching `src/credit_risk/models/`. CI job `check_prereg.py` asserts this.
- **Depends:** D-03 (needs the vintage counts to confirm the splits are viable), before M-01.

## Phase 1: Data
**Entry:** D-01 decided. **Exit:** clean parquet, whitelist enforced by tests, data profile written, splits frozen.

**D-02 ★ Download and load script**
- **Steps:** `src/credit_risk/data/download.py` with `download(source: Literal["kaggle","zenodo"]) -> Path`. Zenodo: stream the file and verify md5 `b019384d6bc65bf2a3e839362e4ff502`. **D-05 Feature leakage and missingness audit**

**D-06 Split materialisation**

## Phase 2: Baselines and the champion scorecard
**Entry:** splits frozen. **Exit:** scorecard with PDO scaling, a hand-computable example and logged validation metrics.

**M-01 ★ Naive and incumbent baselines**
- **Steps:** M0 = constant train bad rate (gives the Brier floor; AUC = 0.5). M1 = LC `sub_grade` ordinal used as a score, with AUC/KS/Gini on validation. Log both to `results/experiments.jsonl`.
- **Acceptance:** M0 AUC is exactly 0.5 (test). M1 is logged with bootstrap CIs.
- **Depends:** D-06.

**M-02 Literature reproduction (Zenodo)**
- **Why:** checks your pipeline against a published number (S14).
- **Steps:** on the Zenodo extract with the paper's setting (5-fold CV, XGBoost/LightGBM default, the same 8 numeric/categorical features, no text), report AUC.
- **Acceptance:** AUC lands within ±0.01 of 0.6575 ([Sanz-Guerrero & Arroyo](https://arxiv.org/html/2401.16458v3)), or the gap is explained in `research/reproduction.md`. Not a gate.
- **Depends:** D-02 (Zenodo). Parallel track.

**M-03 ★ Monotonic binning (WOE/IV)**
- **Steps:** `scorecard.py::fit_binning(X_train, y_train) -> BinningProcess` with `monotonic_trend="auto_asc_desc"` for numeric features, `min_bin_size=0.05`, special code for missing, and `selection_criteria={"iv":{"min":0.02,"max":1}}` (the threshold used in the [OptBinning tutorial](https://gnpalencia.org/optbinning/tutorials/tutorial_scorecard_binary_target.html) · **Medium**). Export the bin tables to `reports/binning/*.csv`.
- **Acceptance:** each selected numeric feature's WOE is monotone across bins (T-07). IV table saved. Features with IV > 0.5 are flagged for a leakage check (heuristic, **Unverified**).
- **Depends:** D-06.

**M-04 ★ Logistic regression on WOE**
- **Steps:** `LogisticRegression(penalty="l2", C` tuned on validation log-loss over `[0.01,0.1,1,10]`, `max_iter=1000)`. Check every coefficient has the expected sign: with OptBinning's WOE convention, verify that higher WOE → lower PD and record the convention in the code docstring. Check VIF on WOE features (flag VIF > 5, **Unverified** rule of thumb).
- **Acceptance:** all coefficients have the same sign, as expected for WOE inputs. Any violator is dropped and logged.
- **Depends:** M-03.

**M-05 ★ Points scaling (PDO) and score bands**
- **Steps:** `scorecard.py::scale_points(log_odds_good, base_score=600, base_odds=50, pdo=20) -> np.ndarray` implementing `factor = pdo/ln 2`, `offset = base_score − factor·ln(base_odds)`, `score = offset + factor·ln(odds_good)`. Defaults follow common convention ([PDtoolkit `scaled.score` defaults: 600, 50:1, 20](https://search.r-project.org/CRAN/refmans/PDtoolkit/html/scaled.score.html) · **Medium**). Allocate per-attribute points as `−(β_j·WOE_ij + β_0/k)·factor + offset/k`. Build 10 score bands (deciles on train) with observed bad rate and mean PD per band.
- **Acceptance:** T-08: (i) +20 points doubles the odds (property test, hypothesis); (ii) the sum of attribute points equals the total score for 100 random rows; (iii) a hand-computed example applicant in `docs/scorecard_example.md` matches the code to the point.
- **Depends:** M-04.

## Phase 3: Challenger, calibration and imbalance
**Entry:** champion fitted. **Exit:** challenger(s) with calibrated PDs, imbalance arm chosen by the pre-registered rule.

**M-06 ★ LightGBM challengers**
- **Steps:** M3 = unconstrained LightGBM; M4 = monotone-constrained LightGBM with `monotone_constraints` from `configs/monotone.yaml`: fico_mid −1, credit_age_months −1, annual_inc −1, dti +1, revol_util +1, inq_last_6mths +1, delinq_2yrs +1, pub_rec +1, pub_rec_bankruptcies +1, others 0. Try `monotone_constraints_method ∈ {intermediate, advanced}` ([LightGBM docs](https://lightgbm.readthedocs.io/en/latest/Parameters.html) · **High**). Tune `num_leaves`, `min_child_samples`, `learning_rate`, `n_estimators` (early stopping on validation log-loss) and `reg_lambda` with Optuna or a 30-point random search, `seed=42`, `deterministic=True`, `force_row_wise=True`.
- **Acceptance:** T-09: the partial dependence of M4 is monotone in each constrained feature on a grid (no violations). Each run is logged.
- **Depends:** D-06.

**M-07 Rolling-origin backtest**
- **Steps:** the 3 folds in docs/02 §5.5 for M2 (scorecard) and M4. Refit binning per fold.
- **Acceptance:** a table of AUC/KS/Brier per fold is generated, with the mean ± sd.
- **Depends:** M-05, M-06.

**M-08 ★ Calibration**
- **Steps:** fit on validation with `CalibratedClassifierCV(FrozenEstimator(model), method=…)` for sigmoid and isotonic ([scikit-learn](https://scikit-learn.org/stable/modules/calibration.html) · **High**). Because the validation year is used for both calibration and selection, use 5-fold cross-fitting inside the validation year to pick the method. Report the calibration curve (10 quantile bins), the calibration intercept and slope, and Brier.
- **Acceptance:** the chosen method is recorded with its numbers. The AUC change from calibration is within ±0.002 for sigmoid (ranking preserved; a test asserts identical rank order for sigmoid).
- **Depends:** M-06.

**M-09 ★ Imbalance comparison**
- **Steps:** for M2 and M4, four arms: (A) natural mix + cutoff chosen on validation; (B) `class_weight="balanced"` / `scale_pos_weight=n_neg/n_pos` then Platt recalibration; (C) `RandomUnderSampler` to 1:1 on train then recalibration; (D) SMOTENC (imbalanced-learn 0.14.2) on train then recalibration. Compare validation AUC (with CI), Brier, log-loss and calibration slope.
- **Decision rule (pre-registered):** pick the arm with the lowest validation log-loss among arms whose AUC is not significantly worse than the best (paired bootstrap, 95%). Tie → A (simplest). Expected outcome per the literature: A ([van den Goorbergh et al.](https://arxiv.org/abs/2202.09101v1) · **High**). Not promised.
- **Acceptance:** `reports/imbalance.md` has the table and the rule applied in code (`select_arm()` with a unit test on a toy table).
- **Depends:** M-05, M-08.

## Phase 4: Evaluation
**Entry:** final candidates chosen on validation. **Exit:** OOT results with CIs, business metrics, stability.

**EV-01 ★ Metric library**
- **Steps:** `metrics.py`: `auc`, `gini`, `ks` (max TPR−FPR, cross-checked against `scipy.stats.ks_2samp`), `pr_auc` (average precision), `brier`, `log_loss`, `calibration_table`, `psi(expected, actual, bins)`, `approval_bad_curve(pd, y)`, `expected_loss(pd, lgd, ead)`.
- **Acceptance:** tests T-10 to T-12 (known-answer cases, below).
- **Depends:** none (can start early).

**EV-02 ★ Out-of-time evaluation (the once-only run)**
- **Steps:** `make final` freezes the config hash, scores the test set for M0, M1, M2, M3 and M4 (calibrated), and writes `results/oot_metrics.csv`. Adds the DeLong test for M4 vs M2 AUC and 2,000 paired bootstrap resamples for ΔAUC, ΔKS and ΔBrier.
- **Acceptance:** the lock file is written. Rerunning with a changed config fails. The CIs are present.
- **Depends:** M-09.

**EV-03 Business view**
- **Steps:** realised LGD on train charge-offs = `(funded_amnt − total_rec_prncp − recoveries + collection_recovery_fee)/funded_amnt`, clipped to [0,1]. Use the mean as LGD (an outcome field used for the loss parameter only, never as a feature). EAD = `loan_amnt` (conservative). EL = PD × LGD × EAD. Curves: approval rate vs bad rate for M2 and M4. Table at approval rates of 60/70/80% (**Unverified** illustrative cutoffs): bad rate, EL per $100 lent, and the change versus the champion. Profit view with an interest-margin parameter `m` (sensitivity m ∈ {0.05, 0.10, 0.15}, **Unverified** values).
- **Acceptance:** charts in `reports/figures/`. The table values reconcile with metrics.py (test).
- **Depends:** EV-02.

**EV-04 Stability**
- **Steps:** per-quarter OOT metrics; adversarial validation AUC (train vs OOT); PSI of score and of each feature, dev → OOT and dev → monitoring 2016–2018, with simulated multinomial critical values ([du Pisanie et al.](https://arxiv.org/pdf/2303.01227) · **High**) next to the 0.1/0.25 rule of thumb.
- **Acceptance:** `reports/stability.md` generated.
- **Depends:** EV-02.

## Phase 5: Explainability
**Entry:** OOT done. **Exit:** reason codes from two methods, with fidelity and stability tested.

**X-01 Global explanations**
- **Steps:** scorecard: points table and IV ranking. M4: `shap.TreeExplainer(model, data=background_500, feature_perturbation="interventional", model_output="raw")` (log-odds; the probability scale is reported for the app only) ([SHAP docs](https://shap.readthedocs.io/en/latest/generated/shap.TreeExplainer.html) · **High**). Beeswarm plot and mean |SHAP| bar chart. Spearman correlation between the scorecard's IV ranking and the SHAP ranking.
- **Acceptance:** SHAP additivity: base value + Σ SHAP = model raw margin within 1e-6 (test).
- **Depends:** EV-02.

**X-02 ★ Reason codes, two methods**
- **Steps:** `reasons.py`. (a) **Scorecard method** (Reg B method 2, [interp. §9](https://www.consumerfinance.gov/rules-policy/regulations/1002/2026-07-21/interp-9/) · **High**): for each feature, `points_shortfall = mean_points_all_applicants[f] − applicant_points[f]`; take the top 4 positive shortfalls. Also implement method 1 (average of applicants at or just above the cutoff). (b) **SHAP method:** top 4 features by positive contribution to PD (log-odds). Aggregate correlated features into reason families first (e.g. fico_mid + inq_last_6mths → "credit score and recent inquiries"). Map each to plain-English text in `configs/reason_text.yaml`.
- **Acceptance:** returns at most 4 reasons; only features actually in the model; deterministic for a fixed input (tests).
- **Depends:** X-01.

**X-03 ★ Fidelity test**
- **Steps:** for 2,000 declined OOT applicants: set the top-1 reason feature to its population-median bin and re-score; measure ΔPD. Compare against the same perturbation applied to a random non-reason feature. Report the share of applicants where the top reason moves PD more than the random feature does ([FinRegLab](https://finreglab.org/wp-content/uploads/2023/07/FRL-ML-EWP_July2023.pdf) motivation · **High**).
- **Acceptance:** report generated. Pre-registered expectation: top reason > random in ≥ 80% of cases (**Unverified** threshold). Below that → flag in the model card.
- **Depends:** X-02.

**X-04 Stability of explanations**
- **Steps:** retrain M4 with 10 seeds (bagging/feature fraction on); compute the top-10 global rankings; Kendall's W; per applicant, the overlap of the top-4 reason sets across seeds (Jaccard) ([Lin & Wang](https://arxiv.org/pdf/2508.01851) · **Medium**).
- **Acceptance:** table plus a flag on features whose rank is unstable.
- **Depends:** X-02.

**X-05 Scorecard vs SHAP comparison**
- **Steps:** agreement rate of the top-1 and top-4 reason sets between methods on the same applicants (using M2 for points and M4 for SHAP, and also SHAP on the scorecard LR via `LinearExplainer` as a sanity check, where SHAP should equal the centred WOE contributions).
- **Acceptance:** the LR-SHAP-equals-centred-contribution test passes (T-13).
- **Depends:** X-02.

## Phase 6: Fairness
**Entry:** reasons done. **Exit:** fairness report with metrics, mitigation trade-off and legal context.

**F-01 Proxy group spike**
- **Steps:** get ACS 5-year table B03002 (race/ethnicity) by ZCTA via the Census API; map ZCTA → 3-digit prefix by string prefix; compute the minority share per ZIP3; join to LC `zip_code[:3]`. Groups: top vs bottom quartile of minority share (proxy). Fallback: `addr_state` only, or skip LC fairness and keep South German Credit.
- **Acceptance:** join coverage ≥ 95% of OOT rows (Phase 1 exit criterion), or the fallback is written in `research/fairness_proxy.md`.
- **Depends:** D-04.

**F-02 ★ Fairness metrics**
- **Steps:** Fairlearn 0.15 `MetricFrame(metrics={"approval_rate": selection_rate, "tpr": true_positive_rate, "fpr": false_positive_rate, "auc": roc_auc_score, "brier": brier_score_loss}, y_true, y_pred, sensitive_features=group)` at the chosen cutoff for M2 and M4. Also `demographic_parity_ratio` (adverse impact ratio) and `equalized_odds_difference` ([Fairlearn](https://fairlearn.org/main/user_guide/assessment/common_fairness_metrics.html) · **High**). Calibration within groups (is PD equally accurate across groups?). Bootstrap CIs.
- **Acceptance:** `reports/fairness.md` table for both datasets (LC proxy, South German Credit age < 25 vs ≥ 25 and ≥ 62 where n allows).
- **Depends:** F-01, EV-02.

**F-03 Mitigation and trade-off**
- **Steps:** (1) `ThresholdOptimizer(constraints="equalized_odds", prefit=True)`, demonstration only, because group-specific thresholds use the protected attribute at decision time (disparate treatment risk; say so); (2) `ExponentiatedGradient(LogisticRegression, EqualizedOdds())` on WOE features; (3) small LDA search: 20 near-equivalent M4 configurations within 0.005 validation AUC of the best, picking the one with the smallest approval-rate gap ([Gillis et al.](https://facctconference.org/static/papers24/facct24-27.pdf) · **High**). Plot AUC vs gap.
- **Acceptance:** trade-off figure, and a table of AUC cost per unit of gap reduction.
- **Depends:** F-02.

**F-04 Legal context write-up**
- **Steps:** one page in `docs/fairness_legal_context.md`: ECOA prohibited bases ([1002.2(z)](https://www.law.cornell.edu/cfr/text/12/1002.2)); adverse-action reasons ([1002.9](https://www.law.cornell.edu/cfr/text/12/1002.9)); the 2026 Reg B amendment removing the effects test, effective 21 Jul 2026, under challenge in D.D.C.; what remains (disparate treatment via proxies, FHA for housing-secured credit, state laws, CRA); EU AI Act Annex III from 2 Dec 2027. Dated, with "not legal advice".
- **Acceptance:** every claim is linked. Reviewed for staleness on the day of publishing.
- **Depends:** none.

## Phase 8: Deployment
**Exit:** public API + app, both live, with a fallback.

**DEP-01 ★ Artefact export**
- **Steps:** `export.py` writes `models/champion.joblib`, `models/challenger.joblib`, `models/bins.json`, `models/reason_text.yaml`, `models/background.parquet` (500 rows, no PII beyond the LC fields) and a `models/manifest.json` (git sha, config hash, metrics, sha256 per file). Size budget < 50 MB in total.
- **Acceptance:** loading from the manifest reproduces the OOT scores of 100 stored rows exactly (T-14).
- **Depends:** MR-01.

**DEP-02 ★ FastAPI scoring service**
- **Steps:** `api/main.py`. `POST /score` takes a pydantic `Application` (whitelisted fields, ranges) and returns `{pd, score, band, decision, reasons[≤4], explanation, model_version}`. Also `GET /health` and `GET /model-card`. Dockerfile on `python:3.12-slim`. Model loaded once at startup.
- **Acceptance:** tests with `fastapi.testclient`: valid input → 200 and schema; out-of-range input → 422; p95 latency < 200 ms locally (**Unverified** target).
- **Depends:** DEP-01.

**DEP-03 ★ Streamlit app**
- **Steps:** `app/streamlit_app.py`: a form with the 12–15 inputs, a "use example applicant" picker, and the result card (score, PD, band, decision, 4 reasons, a plain-language paragraph). Tabs: model card, fairness summary, "how the score was built" (points table). It calls the API if `API_URL` is set and reachable within 3 s; otherwise it scores in-process from the same artefacts (fallback).
- **Acceptance:** Playwright smoke test: load the page, submit the example applicant, see a score. Works with the API down.
- **Depends:** DEP-01, DEP-02.

**DEP-04 Deploy**
- **Steps:** see PLAN §10.
- **Acceptance:** both URLs respond. README badges point to them.
- **Depends:** DEP-03.
